## Services (systemd --user)
| Job | Unit | Restart behaviour |
|---|---|---|
| Bridge guard | `campus-bridge-guard.service` | always / restart on failure every 30 s |
| Capture listener | `campus-capture.service` | always |
| One program: calendar + report + chat | `campus-web.service` = tools/talk.py (127.0.0.1:8790 only) | always |
| Daily run | `campus-daily.timer` + `.service` | persistent |

NapCat itself is NOT a service: the container has restart policy `"no"` and only the guard starts it.

## First run (summary; full steps in README-INSTALL-LINUX.md)
1. Key: `./cnb.sh key set`, then `./cnb.sh key test` (key never printed; stored in `stack/.env`).
2. QQ: `bridge_guard.py --qr`, scan with your own phone QQ, `--status` must say `online`. State `needs_qr` = you must scan; cap 6 per 24 h;
   never start/restart the container yourself; no password or code is ever requested or shared.
3. Groups: your numbers in `capture/groups.json`.
4. Troubleshooting table in the README.

## Excluded from every package (privacy)
`stack/.env`, API keys, QQ numbers, `stack/data` (NapCat login state), `qrcode.png`, all databases, `reports/`, `cache/`, logs,
backups, `stages/`, real `groups.json`, interests/profile data, `*.bak`, `__pycache__`. Templates are shipped instead.
